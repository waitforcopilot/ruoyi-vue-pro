# F-02b 评审负责人分派校验（2026-10-18）

## 问题及修复边界

起点30a2402220已有独立确认权限，但普通save仍无条件写请求reviewerId；维护者能改变服务器保存的分派人。按PRD9.1/AC-18，本项在保存事务内增加统一分派鉴权，覆盖新增带评审人、修改及清空评审人，不能靠改请求绕过。

- reviewerId变化需要独立`hrm:payroll:requirement:assign`，且不能将新分派人设置为操作者本人，超级管理员也不能自派。
- 目标非空时，须有效且具有需求query和confirm两项权限；分别检查，任一缺失拒绝。分派人保存仍需要旧update入口权限，本项尚非无需编辑权的独立分派接口。
- 未改变分派人时普通内容维护保持可用；已有历史自派不被自动重写，旧签字不抹除。已确认行改派仍触发修订重审；确认始终核对数据库保存的当前分派人与操作者。
- 界面无assign时禁用负责人选择框，提示不可自派和目标权限要求；服务器独立鉴权，不以控件禁用代替安全校验。下拉仍列出原有有效账号；目标资格以保存时服务端校验为准，未实现项目候选成员过滤。
- 新迁移`sql/mysql/upgrade/20261018-hrm-requirement-assign-permission.sql`在需求菜单下增加动作，须先应用20261010需求菜单迁移。无自动授权，无system_role_menu变动。既有维护者可继续维护内容，指定/改派负责人需管理员按既有流程授权。
