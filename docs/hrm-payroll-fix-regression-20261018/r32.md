# R32 管理端批次加载失败被显示为无数据（2026-10-18）

## 实际反例

内嵌浏览器管理端选隔离主体4、草稿批次7，正常存在工单1。暂停本机Java进程42926（端口48080），同时设置45秒自动恢复保护，点击刷新，等待项目实际30000ms超时。原版结束后仅显示“暂无数据”，无持续失败状态；控制台出现AxiosError timeout of 30000ms exceeded（09:55:41 UTC），见[r32-before.png](r32-before.png)、[页面树](r32-before.txt)。不是已发生的错误提交，而是把加载失败与没有工单混淆。

原代码刷新即清空工单、员工及检查结果，但仅有finally解除loading，没有失败标记或持久重试指引；Promise.all任一读取失败都会无法应用整组结果。

## 修复

增加批次读取失败标记，当前工单或员工读取失败显示“批次工单或员工加载失败，当前状态尚未确认。请点击刷新重试后再处理。”空表区分未选批次、加载中、读取失败、成功无工单。重试及切换主体清除旧失败状态，仍沿用原刷新入口。

复用主体、批次及请求版本校验，只有当前请求失败可以设置标记；旧失败或成功均不能覆盖新请求。读取失败由本页捕获，不向组件事件继续抛出。不改授权、业务状态或请求超时配置。
