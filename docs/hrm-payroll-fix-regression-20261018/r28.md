# R28 员工端迟到履历响应上下文（2026-10-18）

## 实际反例

本机内嵌浏览器，账号1绑定合成员工8、工单1。与R26普通页面往返不同，本轮实际让履历GET请求在离页时尚未返回：短暂SIGSTOP本机Java进程16522（端口48080），同时启动30秒自动SIGCONT保护；浏览器点击履历后立即后退首页，随后手动SIGCONT恢复Java，再点击工单页签返回。

返回页面时没有再次点击履历，旧响应却自动打开履历弹窗。见[r28-before.png](r28-before.png)、[记录](r28-before.txt)。这证明R26未复现的迟到读取场景本轮已实际复现；不是声称旧履历覆盖首页，也不是后端越权。

## 修复

履历查询绑定独立请求版本、列表版本及工单/批次/员工，要求当前行仍在当前列表。新查询清空原履历，只有有效上下文的响应能设置events并显示；刷新、KeepAlive停用及卸载关闭并清空履历，使迟到响应失效。弹窗标题明确工单编号。使用现有授权接口，未修改后端权限、工单数据和材料提交规则。

## 实际内嵌浏览器回归

1. 整页重载新版，重建首页→员工端的导航顺序，确保当前工单列表加载。
2. 按相同SIGSTOP/30秒自动恢复保护步骤点击履历、后退首页；手动恢复Java后返回员工端，未再次点击履历：没有旧履历弹出，见[r28-after-return.png](r28-after-return.png)、[记录](r28-after-return.txt)。
3. 主动点击履历，标题“工单处理履历 #1”，正确显示原创建、两次交接、R21提交及退回五条，日期和操作人保持，见[r28-history.png](r28-history.png)、[记录](r28-history.txt)。关闭、刷新、再次主动打开仍正常。
4. 两次自动恢复保护进程均已退出，Java已恢复运行；前端HTTP200、后端健康HTTP200/UP。浏览器error日志为空。本轮只读操作，没有提交材料、交接或任何工单状态变更，原工单继续待补正。

本轮不是浏览器网络限速模拟，而是本机后端进程短暂停顿后的真实迟到响应。没有修改网络配置；暂停期间没有执行其他业务写入。
