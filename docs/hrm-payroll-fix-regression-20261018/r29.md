# R29 员工端刷新失败后旧工单仍可处理（2026-10-18）

## 实际反例

本机内嵌浏览器员工端薪酬工单，账号1绑定合成员工8、工单1待补正。短暂SIGSTOP本机Java进程16522（端口48080），设置45秒自动SIGCONT保护；点击刷新，等待项目配置的30000ms超时。原版刷新结束仍显示旧工单、没有持续失败状态，点击“补充材料”可打开材料弹窗。见[r29-before.png](r29-before.png)、[记录](r29-before.txt)。未填写或提交材料，取消弹窗，随后手动恢复Java。原版控制台记录AxiosError timeout of 30000ms exceeded（09:38:25 UTC）。

这不是已发生的越权或错误服务器提交，而是刷新失败后继续把旧列表当作当前可操作结果的前端缺口。

## 修复

刷新/重新加载时立即清空旧rows、重置失败标记；当前请求失败设置明确错误状态，提示“工单加载失败，当前状态尚未确认。请点击刷新重试后再处理。”失败空表显示“工单未加载，请刷新重试”，与成功无工单及加载中区分。重试沿用原刷新入口。旧响应或失败仍须匹配页面及列表版本，不能覆盖新的状态；提交与履历沿用当前行存在校验，因此空结果不可继续处理。

捕获列表读取失败，显示错误状态而非向组件事件继续抛出；不修改后端授权、请求超时或业务状态。

本轮使用本机后端短暂停顿，未修改网络配置，没有业务写入，未删除超时日志。
