# F-02a 维护与确认权限拆分（2026-10-18）

## 问题及实现

起点54479ab959的confirm和save都使用`hrm:payroll:requirement:update`。在本机内嵌浏览器实测：既有操作账号hrmacceptoperator/251拥有query/update/export，作为合成需求47的评审负责人，仍能确认版本13并生成版本14。见[旧行为](f02a-before.txt)、[截图](f02a-before.png)。这说明维护授权同时赋予确认能力；本人检查不能替代专用动作权限。

新增`hrm:payroll:requirement:confirm`，confirm入口同时要求query和confirm。维护、初始化、历史及导出沿用各自旧权限；确认继续执行有效人员、负责人本人、已保存版本及材料校验。界面确认按钮使用confirm，编辑仍用update。

增量迁移`sql/mysql/upgrade/20261018-hrm-requirement-confirm-permission.sql`在既有需求菜单下增加动作项，可重跑，不修改任何system_role_menu。部署时先应用20261010的需求菜单迁移，再应用本迁移；既有非超级管理员维护账号不会自动获得确认权，需要按既有管理流程显式分配确认权限。专用确认角色还需query，否则拒绝读取及确认。未新增测试账号、未给现有账号扩权。
