# F-03b 保存内容与确认版本分离（2026-10-18）

## 契约及兼容边界

原审计F-03要求普通保存不同时生成新签字。F-03a已修关键修订清签，但待评审行仍能保存CONFIRMED来确认。本项新增独立`POST /hrm/payroll/requirement/confirm`，请求仅id和version。服务端锁定记录、检查版本和可确认状态，再从数据库已保存行构造确认内容，复用完整性、有效人员及评审人本人校验，事务保存签字和历史。确认不接收客户端内容修改。

普通save不能为新建/未确认记录生成签字：直接传CONFIRMED返回1050810040，提示先保存再确认。已确认行无关键修改的普通保存继续保留原签字，关键修订沿用F-03a转评审中并清签。重复确认、暂缓或旧版本不能新签；readiness独立保留。

前端编辑下拉禁用已确认，列表增加“确认版本”按钮，弹窗明确需求ID/编号及已保存版本。非本人禁用；取消/关闭不请求，离页/模块/行版本变化不发送旧确认，重复点击互斥。前端保留普通保存误传确认的提示，服务端独立拒绝，不依赖界面禁用。

确认路由沿用已有requirement:update接口权限，未增加授权或新角色。F-02专用REQ_CONFIRM及项目分派/成员撤销尚缺，本项不声称完成动作级授权。项目范围未定义时沿用当前旧评审语义，不冒称可发布或完成新PRD正式确认闭包。
