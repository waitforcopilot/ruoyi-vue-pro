## 安装

1. 基于现有 yudao 数据库执行 `sql/mysql/hrm.sql`。
2. 每个已交付模块执行对应的增量脚本，以本页各模块安装说明为准；尚未交付的脚本不属于已验收安装范围。
3. 为业务角色授权新增菜单及按钮；使用租户套餐时同时配置套餐可用菜单。
4. 进入“薪酬管理 → 需求评审”，初始化 PRD 清单。初始化不自动代表业务确认或数据就绪。

需求模块保留历次评审内容及操作人，重新评审会清除当前确认标记；已确认需求仍需单独维护真实数据就绪情况。

## 核算审批说明

新增“薪酬管理 → 核算审批”，可查看所有月份的当前状态、核算版本及审批记录。核算人、HR 复核人和财务审批人必须不同；发放必须从冻结状态由代发模块发起。原有已核算但无版本快照的数据需重新核算后才能提交审批。

创建下月或删除最新草稿不会改写上一月状态。人工调整已试算工资会保留原版本，并保存新结果及操作人；审批使用最新版本。银行台账完成后才允许归档。

## 银行代发说明

进入“薪酬管理 → 银行代发”，选择已冻结批次，生成代发明细，再按银行模板导出 Excel。模板分别保存代发列及回盘列的名称、顺序、成功/失败取值；变更配置创建新版本。保留代发明细编号和发放次数，供回盘定位及过期校验。

导入前预览批次、账户、金额、重复编号、发放次数和状态差异。存在差异时不修改台账；匹配后可处理部分成功/部分失败。重试仅将失败项加入待发明细，成功项不会再次导出。重复文件按批次与内容摘要防重，回盘记录保留来源文件、操作人和数量。此模块提供文件对接，没有接通银行直连。

## 加班认可、调休与工时周期

安装 `sql/mysql/upgrade/20261010-hrm-work.sql`，授权“薪酬管理 → 工时与加班”。员工制度按生效区间维护并由其他人员批准；标准、综合、不定时分别处理。工作日/休息日/法定节假日采用排班和字典值3的法定日历识别，不能由客户端指定。倍率、时薪、周期标准分钟、周期月数、月上限和调休有效天数记录适用依据。

加班核实必须引用已批准 OA 申请、员工关联用户及真实上下班打卡编号。服务端采用批准时段与打卡交集，扣除休息及正常班次重叠，跨日自动按日期拆分；跨日含人工休息分钟需按日明确分配。缺少映射、批准记录、制度、打卡或有效时段则阻断；同来源同日期或重叠加班不能重复认可。记录保留审批、打卡及日类型快照。冻结时复核审批和打卡；人工调整版本沿来源运行追溯，不能丢失来源核验。

标准工时休息日可转调休，记录金额为零。调休按额度到期日优先分配，申请凭证防重；占用后核销，退回按原额度归还。已过期额度退回不延长有效期，也不能核销。工作日及法定节假日不允许用该调休入口代替加班费。存在认可来源时，来源金额（包括零）覆盖旧手工加班金额。

综合工时非节假日不逐日发放加班费。完整批准周期结束后，将真实打卡工时（扣班次休息、排除法定节假日）与周期标准分钟核对，超出部分以批准认可分钟为上限，按工作日倍率结算；法定节假日独立按日计薪。周期金额在结束日期所在计薪区间进入工资，周期和原始输入快照不可变。应结算而未结算的完整周期阻断工资试算。不定时工时的非节假日不套用标准加班倍率；法定节假日按批准制度计算。

本次交付提供月度上限预警及排班/实际/认可周期明细。源记录更正工单、跨周期异常处置、按制度联动考勤扣款，以及多法人/补发批次下来源分配防重复，仍需后续模块补齐；不将这些条目标记为全部完成。

员工端仅显示本人、责任人或指定复核人可访问的工单及证据；跨员工提交与履历访问校验在服务端执行。逾期提醒在工单页面和员工端展示。未关闭工单阻断涉及人员和期间的同步试算/冻结；没有考勤组不按满勤核算。

核算快照保留员工适用期、打卡、批准覆盖、考勤组及班次。冻结前重新比对；人工调整版本继续沿来源核算运行追溯。来源变化需要补正、重算和重新审批，不改写历史快照。已发放结果的补发更正、非同步输入的强制就绪确认和按工时制度调整扣款，仍在后续交付范围内。
