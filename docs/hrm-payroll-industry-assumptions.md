# 薪酬 PRD 补充：行业惯例与首期实施口径

版本 v0.2，2026-10-07。用户已授权对未明确需求按行业惯例推理并补充 PRD。以下是本项目的研发实施默认值与可配置边界，替代“缺少业务签认即停止编码”的前置限制。它们不表示已获得某企业 HR/财务签字，也不把原型示例当作实际人员、工资或缴费数据。

## 推定口径

| 原问题 | 采用的首期口径 | 配置与校验 |
| --- | --- | --- |
| Q-01 主体和人员 | 租户内可登记多个声明主体，每批工资属于一个主体；批次人员显式列出，以 HRM ID 为身份 | 主体编号与名称必填；人员资格须由已确认版本覆盖完整期间；排除资格不生成零金额；不根据当前部门猜法人归属 |
| Q-02 周期与截止 | 工资默认自然月，开始为月初、结束为月末；支持明确自定义期间 | 期间包含两端；自定义最多 366 天；不同来源不得自动拼接或跨期填补；同一批次身份固定主体与期间 |
| Q-03 薪资项 | 应发=基本工资+绩效金额+津补贴+已核定加班金额；工资扣款=缺勤扣款+个人社保+个人公积金+其他扣款；实发=应发−工资扣款−代扣个税 | 提供可编辑规则模板，四个结果角色显式绑定；全部输入须明确供给，真实零值输入 0；个税和缴费额在相应计算模块接入前由有依据的输入提供 |
| Q-04 加班 | 仅纳入有效批准且已核定的加班记录；标准工时的工作日/休息日/节假日倍率建议 1.5/2/3 | 倍率、调休抵扣、认可时长和制度均版本化；特殊制度不自动套用标准工时；本轮不从空审批记录生成加班金额 |
| Q-05 不足月 | 默认按已登记的应出勤和实际计薪天数折算；分母不可为空或为零 | 工资模板保留可配置表达式；21.75 不作为所有不足月场景的固定分母；入离职、调薪、请假规则按明确的期间与输入处理 |
| Q-06 流程 | 草稿→资料核验→试算版本→复核→冻结→发布/发放→归档 | 维护、试算、复核分别授权；未完成资料核验不能直接执行；重算生成新版本；审批/冻结/付款状态分别记录并逐模块接入 |
| Q-07 社保公积金 | 本地已确认政策版本和缴费账为依据，个人与单位金额分别处理 | 地区、项目、有效期、基数上下限明确；缺缴费输入阻断，不自动当作 0；基数与比例不从网页示例复制 |
| Q-08 个税 | 按纳税主体、人员和税务年度管理累计口径 | 首期试算可以使用有依据的代扣税输入；累计税模块后续接入既有计税规则；缺累计资料不能伪造税额或历史已扣税 |
| Q-09 数据来源 | 优先复用 HRM 只读数据与受控导入，必要时使用明确的人工确认输入 | 每位人员保存输入依据、变量、规则版本、资格版本及快照；外部接口另行配置实际认证，不阻止本地模块编码 |
| Q-10 工资条 | 员工仅查看本人有效发布版本；工资条与投递结果分别记录 | 复核和冻结后才能发布；撤回、重发有版本与幂等标识；实际邮件/银行发送不在回归中执行 |
| Q-11 精度 | 首期币种 CNY，金额 2 位、HALF_UP；除法默认保留 8 位再按项目舍入 | 规则模板采用默认值，明确版本可以配置；批次的应发、扣款、个税、实发角色必须是 CNY/2 位，合计由个人已舍入金额相加 |
| Q-12 权限和保留 | 租户隔离，部门/本人范围同时校验当前及抓取组织；原始输入、结果及变更证据保留 | 第一版每批最多 100 人，超限分批；批次历史涉及的所有人员须可访问，防止汇总泄露；默认不自动删除历史，保留期限另行配置 |
| Q-13 首期范围 | 先完成人员、规则与批次试算，再接入复核冻结、正式来源、社保/税务和付款工资条 | 每个模块独立回归、截图、提交；未接入功能保持真实状态，技术通过不当作全业务完成 |
| Q-14 工时制度 | 支持标准、综合、不定时三类制度及有效期 | 制度来自人员档案/批准依据，缺失时提示；不把原型“有异议”解释为取消工时管理 |
| Q-15 职级绩效 | 岗位系数、薪级薪档和补贴标准以有效版本映射工资项目 | 优先批量维护/导入，绩效结果确认后接入；缺职级或结果不能用默认奖金补齐 |
| Q-16 银行代发 | 首期支持可配置文件模板与回盘核对，银行直连单独接入 | 批次、明细、文件和回盘分别幂等；成功付款不重发；实际银行账号和接口凭据是部署配置，测试使用合成资料 |
| Q-17 年终奖 | 作为独立业务批次及可配置计税方式 | 引用适用年度的政策版本，保留选用依据；不假定每个主体均能采用同一优惠方式 |
| Q-18 成本报表 | 明确成本中心/项目分摊；合计回到员工成本 | 比例合计 100%，舍入尾差按确定规则分配；缺预算、营收或分母时不展示虚构人效指标 |
| Q-19 工时异议 | 制度依据、来源差异和例外通过记录与核定流程处理 | 保留异议和责任人，按确认版本核算；不以争议状态隐式填零 |

## 本轮模块：批次资料核验与版本化试算

1. 批次登记主体、期间、明确的人员清单、计算规则版本、负责人和口径依据；每位人员录入十进制字符串输入与来源依据。
2. 使用已确认人员资格和已确认计算规则。资格或规则缺失、停用、未覆盖完整期间、人员档案变化、输入缺失/错误和金额角色不一致均报告受影响人员，执行接口统一重新检查。
3. 应发、工资扣款、个税、实发分别绑定所选规则的结果键，必须为 CNY/2 位；实发必须精确等于应发减扣款减个税。常规工资批次不接受负数输入或负数金额，退款/追溯调整在后续带依据的调整批次接入。
4. 明确排除资格的人员列为排除，不参与金额合计、不生成零工资。无法核定资格为阻断。全部人员被排除时不能生成空工资版本。
5. 资料核验返回内容指纹；正式执行重新核验，指纹或修订改变则要求刷新。执行锁定批次、规则系列、资格系列和人员主档，防止读取混合版本。
6. 每次成功试算保存不可变版本：批次口径、来源输入、人员/资格快照、规则定义/指纹、逐项计算解释与个人/批次金额。修改草稿不覆盖历史版本；重试幂等键不重复生成版本。
7. 同批次版本差异逐人展示新增、移除、排除、输入和金额变化，金额按角色与单位核对，合计可回到个人结果。
8. 第一版新增业务批次与结果表，不修改既有月工资、工资条、社保月账或已发放金额。复核冻结、来源契约自动映射、方案项目绑定和税务累计分模块接入。

验收以正常工资、明确零值、缺数据、明确排除、停用/跨期、主档变化、错误净额、并发重试、历史重算、跨租户和部门/本人权限为必要用例。示例工资仅用于技术回归；运行时由业务用户配置实际人员、金额和依据。
