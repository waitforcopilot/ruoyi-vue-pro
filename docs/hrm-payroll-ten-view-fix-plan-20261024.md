1. 本机内嵌浏览器进入正确TEST项目/模块，页头、范围、示例标识、正常例和异常例明确；不能用受限账号空清单证明内容齐全。
2. 完成该任务表中的正常/异常演示；比较结果或状态前后有可观察变化。若内容采用结构化静态对照而非按钮，记录可见数据及其PRD映射，不虚构动作。
3. 每个视图至少保存1条围绕真实候选点的TEST意见，共10条；刷新和历史读取证明持久化，返回对应模块/锚点。46个卡片只需逐项核对编号/内容/锚点/入口存在，不强制保存46条重复意见。
4. V01覆盖四类征集入口；单个模块新增特殊表单时验证其字段/例外输入保留。已有通用能力不重复记成十份已开发功能。
5. 页面网络和日志证明演示不调用正式核算、审批、付款、税务、工资条发布或消息外发接口；真实意见保存允许调用评审API。

### 5.2 角色、视口、错误及对账

- 业务角色HR/主管/财务/需求负责人是测试场景视角；实际登录账号、数字ID、项目动作授权及作用范围单独记录。既有合成编辑/评审账号不等于真实HR/财务批准。使用现有最小权限TEST账号，缺权限先记录具体阻断，不为获得PASS随意扩大权限。
- 390/768/1440 CSS视口各完成至少一组提意见→选择有权实际来源（或明确不适用）→保存→刷新→历史→返回；每个视图在390宽检查关键操作可触达、宽表可横滑。模块新增专有表单时在三视口测试该表单；不要求无意义的46×10×3全乘积。
- 缺来源、无权、真实空结果、加载中、接口失败分别核对；保存失败后输入保留、无新成功版本，恢复后只保存一次。故障模拟使用安全TEST夹具/测试能力，不破坏共享本机数据库或长期中断服务；不能实际浏览器验证的分支列未执行。
- 固定主样例：基本10000＋绩效1000＋加班750＝应发11750；个人缴费1400、演示税130.50、实发10219.50；单位缴费2100、用工成本13850；排班160、出勤152、带薪假8；预算14000、差额-150。候选调薪10500、奖金、补缴情形等使用独立场景键，不能悄然改变该主样例。
- 候选/来源/问题/统计/导出只对同项目、同范围版本、同过滤条件对账；受限节选按其可见集合核对，隐藏对象和数量不推测。历史固定快照与当前筛选清单分别验收。
- 优先给新增示例计算/状态流转写有意义测试：前置条件、跨模块/项目重置、未知处理、金额一致性和补偿去重。按实际改动运行目标静态检查及`pnpm build:local`；如`pnpm ts:check`有既有失败，保留原始输出并判断新增差异，不伪称全量通过。后端未变不机械重跑所有后端测试，改动后再选相应套件。
