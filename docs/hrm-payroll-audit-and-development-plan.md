## 1. 结论与审计口径

以 yudao 为基础实现 PRD 的 10 个视图、43 个业务功能点及 COL-01～03。已有薪资、考勤、社保和工资条后端可以复用，但当前仓库没有完整 HRM 前端，缺少关键业务闭环和正式集成条件。

以下状态描述后端代码覆盖程度，不代表通过部署或业务验收：

- 基础已实现：能定位到主要业务实现；仍需前端、集成及运行验证。
- 部分实现：已有可复用对象或逻辑，但缺少需求中的关键能力。
- 未发现实现：在本次检索的 HRM、OA 及当前前端中未发现对应完整业务能力。

本次为静态审计。环境没有 Maven，未执行编译、测试或服务启动；不能以测试源码数量宣称测试通过。没有读取配套原始 HTML，43 项原型功能以 PRD 附录 A 为准。未访问外部政策网站或银行、税务接口。

默认主服务未启用 HRM。HRM POM 直接依赖 BPM；复用 OA 加班、出差等流程时，还需按依赖关系接入 OA，并通过模块 API 适配，避免业务模块相互依赖。租户隔离不能代替法人主体、纳税主体和成本中心建模。

### 3.11 横向交付缺口

1. 前端：当前 yudao-ui 各目录主要是外部仓库说明，Vue3 只有少量 MES 文件；没有 package.json 或 HRM 页面。需接入与当前 API 兼容的 yudao Vue3 前端，补齐全部 10 视图及员工入口。
2. 数据库：MySQL 主初始化脚本没有 HRM 表；测试目录有 H2 建表资料，但不是生产迁移脚本。需准备 HRM、BPM、必要 OA 表和数据迁移、菜单、字典、流程模型与消息模板。
3. 权限：已有 Controller 权限及员工本人校验可复用；需补法人主体、组织历史归属、薪资字段、导出和审批授权，并验证服务端隔离。
4. 审计及幂等：已有操作日志和行锁；需补来源编号、导入批次、幂等键、数据库唯一约束、状态历史、版本不可变及通知重试。
5. CI：现有 Maven workflow 跳过测试，前端 workflow 指向不存在目录；需要 HRM 构建及真实测试流程。

## 5. 未明确需求的默认实施规则

用户已授权按行业通用流程推进；本节作为开发默认设计，不将不明确内容无限期挂起。业务后续可通过版本化配置调整。

1. 范围：面向中国大陆工资、个税、社保公积金业务；租户下显式区分法人主体、纳税主体、部门及成本中心。员工类型、城市和工时制度按有效期关联。
2. 期间：默认自然月、每主体每期间一个常规批次；允许关联原期间的补发 / 更正批次。考勤截止、跨月计薪和发薪日可配置。
3. 流程：草稿 / 数据准备→试算→HR 复核→财务审批→冻结→发放中→回盘对账→已发放→归档。驳回回到可修订状态；重算产生新版本并使原审批失效。已发放结果通过补发 / 更正调整。工资条发布状态与银行付款状态分别记录。
4. 定调薪：申请→主管审批→HR 审核→按有效日生效，调薪记录与方案版本不可变。月中变更按日分段；日历日 / 应出勤日折算为可配置策略，默认保持已有日历日加权以兼容，回溯影响单独提示。
5. 薪资项与公式：固定、浮动、补贴、扣减、个人缴费、单位成本分别建模；采用受限表达式及白名单变量，校验依赖和循环，禁止执行任意 Java / 脚本。公式可解释并引用生效版本。
6. 输入：必须有来源、员工匹配、期间、单位和就绪状态；缺失不能自动当零。真正无发生额明确确认零值，非适用项显式豁免。导入先预校验，失败行可下载，重复处理必须显式选择。
7. 考勤：审批通过的请假、出差、外出及补卡参与判定；保留原始打卡。异常工单由员工 / 主管补正、HR 复核关闭；源数据变化标记关联工资版本受影响。
8. 加班与调休：审批时段与实际打卡、班次交叉核实，扣除休息和重叠时段，形成认可分钟数。按日类型、制度和生效规则计算。加班费和调休避免重复补偿；调休采用额度账本。倍率、时薪基数、上限及补休有效期配置化。
9. 工时：维护标准 / 综合 / 不定时制度及适用依据。综合工时按配置周期归集，不定时工时采用独立规则，不套用统一倍率；无法匹配制度规则时阻断涉及金额的核算。
10. 社保：城市 / 项目 / 生效期维护上下限、个人及单位比例或固定额，年度调基审批；个人扣款与单位成本分开。政策正式生效需记录出处和维护人，抓取仅作参考。
11. 个税：工资累计预扣按纳税主体及年度连续计算；支持授权导入历史累计和专项附加扣除。年终奖支持单独 / 合并计税策略及年度有效期。政策参数依据正式适用规则维护，不从原型示例推导。负预扣进入更正记录，不自动增加工资。
12. 发放：先实现配置模板的银行代发文件及回盘导入，无银行直连依赖。按发放批次、员工、账户和金额校验；部分成功仅重试失败明细，成功项防重复发放。
13. 工资条：默认员工自助及站内通知，扩展邮件 / 短信渠道；外部通知使用受控访问链接，投递状态、重试与撤回留痕，不能因渠道未配置阻断工资条生成。
14. 精度：金额 BigDecimal，展示到分；计算中间精度和舍入顺序按规则版本保存，默认 HALF_UP。原始时长以分钟保存，显示小时。汇总采用明细结果，成本默认应发加单位社保公积金及配置单位成本。
15. 报表：默认当期部门归属，支持成本中心 / 项目分摊，比例总计 100%。预算版本化；缺营收或人数时显示不可计算，不造零或虚假指标。导出默认 XLSX，可配置 CSV 银行模板。
16. 征集：初始化候选点为待确认，优先级作为候选值。流程为待确认→评审中→已确认 / 有异议 / 暂缓，记录依据及责任人；数据就绪另设状态。需求评审状态与研发完成状态分开，版本化导出。
17. 安全与审计：查看、维护、核算、审批、发布、导出分别授权；关键流转记录操作人和理由。采用服务端范围校验、并发锁和业务唯一约束；历史快照保留必要敏感数据并限制访问。

### 6.1 建议新增领域对象

以下为设计工作包，不是声称已存在的表。优先扩展现有对象，避免另建一套重复工资系统。

- 主体与归属：法人 / 纳税主体映射、员工历史归属、成本中心及项目分摊配置。
- 需求与数据：征集需求、评审历史、数据源及字段映射、导入批次与行错误、异常工单。
- 规则：薪级薪档、方案版本、公式版本、定调薪审批关联、工时制度适用、社保政策版本、税务年度规则。
- 输入：认可加班、调休账本、工时周期结算、社保实缴 / 补缴、税务扣除及累计资料。
- 核算：运行版本、输入快照、员工结果版本、计算步骤、审批 / 状态历史、补发更正关联。
- 发放与分析：银行模板、发放明细 / 回盘、工资条投递与异议、税务文件批次、预算版本及成本分摊结果。

新增主体 / 批次唯一键不能直接替换现有年月唯一查询。需显式迁移旧数据、更新 Mapper、累计税关联与工资条防重逻辑，兼容既有状态值并定义历史记录映射。

### 6.2 数据源落地策略

DS-01 / 02 / 05 / 06 / 09 / 11 优先复用 HRM 对象和 system 消息能力；DS-03 通过 OA / BPM 模块 API 适配；DS-04 新增制度及工时归集；DS-08 新建征集模块；DS-07 / 10 / 12 首先提供有校验的模板导入与真实导出。每类来源均支持记录源系统、源记录编号、导入批次、有效期和责任人。

未提供具体外部系统时，模板导入及人工维护是可用的数据接入路径；API 适配器保留扩展点。银行直连、税务直报和未知第三方接口不作为完成候选功能的隐含前提，也不能标记为已接通。

### 6.3 首个可验收里程碑

完成 M0～M1：前后端可启动、HRM 权限可验证，10 个视图具备真实导航，需求征集可保存 / 留痕 / 导出，数据导入及核算准备检查可用。尚未完成的业务操作明确显示开发状态，不显示虚假的核算或发放成功。

完成 M2～M3 后可验收完整试算与审批；M4 后可验收文件代发及工资条闭环；M5～M6 后验收完整 PRD。当前没有据人员数量和实测吞吐推导工期，不提供无依据的完成日期。

## 7. 验收及测试计划

1. 复用已有 244 个 @Test 作为回归基线；实际通过数量以执行报告为准，补新增关键业务测试。
