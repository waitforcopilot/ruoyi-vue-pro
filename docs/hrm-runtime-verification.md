## 数据库安装

全新测试库先执行 `sql/mysql/ruoyi-vue-pro.sql`。该上游脚本包含删除旧表操作，不能用于已有业务数据库。

已有 yudao 数据库按顺序执行 `sql/mysql/hrm.sql`、`sql/mysql/bpm.sql`、`sql/mysql/oa.sql`，再执行已交付模块的增量脚本：

完整依赖顺序由 `scripts/hrm/migrations.txt` 维护，覆盖基础业务表及全部已交付增量；不能按同日文件名字母排序推导依赖。安装器使用显式指定数据库，普通升级不执行上游删表脚本：

```bash
python3 scripts/hrm/migrate.py --container <测试MySQL容器> --database <已有测试库>
```

仅对新的隔离测试库使用 `--fresh`：先创建数据库再安装上游基础表；若数据库已存在则拒绝执行。已有业务库在升级前执行一致性备份，不使用 `--fresh`。所有业务与增量脚本显式初始化 UTF-8，不依赖客户端默认连接字符集。

```bash
python3 scripts/hrm/migrate.py --container <测试MySQL容器> --database <全新隔离库> --fresh
```

最后的 `20261016-hrm-installer-charset.sql` 只修复与已提交安装标签完全相等的 latin1 误解码，按菜单组件/权限、模板编码、任务处理器或工资项编码限定；保留自定义标签、审批、金额和任务启停。模板修复同时覆盖保持原安装名称的租户工资项，不覆盖人工改名。

安装扣除资料迁移后，对每个使用薪酬的租户执行现有 `PUT /hrm/salary/option/sync`（`hrm:salary:option:update`）同步新增 `260106` 婴幼儿照护、`10901` 工资差额、`150901/160901` 税款收退及 `150902/160902` 缴费差额目录项；保留原启用/展示设置。目录项缺失或归属错误时主体工资核算会阻断，不静默忽略非零扣除。旧已复核的五项扣除输入需按六项模板明确补齐并重新复核；不能自行给缺项补零。

三个基础模块脚本仅创建缺失业务表。Flowable 使用项目现有的自动升级配置创建流程引擎表。后续模块的增量脚本应随相应功能交付安装，不能仅凭文件存在判断已验收。

## 居民工资年度预扣准备顺序

1. 安装至 `20261014-hrm-tax-withholding.sql`，按租户同步薪资项目录；配置独立身份加密/指纹密钥。旧资料中的新增资格字段保持未知，须提交新年度档案版本，不能批量默认为符合。
2. 主体人员分别取得维护、核算、复核和批准范围。维护正式年度居民政策并独立批准；员工年度身份资料明确居民资格、额外历史累计及首次工资在新入职前的工资/连续性劳务条件，再由独立人员复核。
3. 按计划实际发放年度/月准备六项累计扣除申报资料，独立复核。维护工资批次计划日期，历史累计输入选择“按计划发放年度同步已发现金来源”，完成批次独立复核；已有实际现金与扣除资料时不能手填不同金额绕过。
4. 核算引用正式政策和来源快照，HR复核/财务审批绑定运行版本，冻结时重新核对来源。同一纳税人/主体/年度的待发运行串行占用；成功结清该人员后才允许下一运行占用，部分成功不把已结清人员作为未支付来源重新校验。
5. 导出待发文件前重新核验未结清人员来源。成功回盘记录实际日期，已发数据不可改写。到账月份或扣缴主体与冻结税务资料不一致时台账标记需更正，禁止继续把不一致资料作为年度累计；通过后续更正流程处理，不删除原到账事实。

以上为已实现居民工资链路，非居民及其他税务模型不能自动套用居民累计参数。年终奖年度使用、税务更正及申报完税对账仍随各模块补齐；完整运行/浏览器验收仍按最后交付阶段进行。

## 启动

服务器使用项目 Maven 构建 `yudao-server` 及其依赖。配置 MySQL 主、从数据源及 Redis，运行时设置 `-Duser.timezone=Asia/Shanghai`。隔离测试环境关闭 Quartz 自动启动、关闭模拟登录，避免启动业务定时任务。

Vue3 目录安装锁定依赖后运行 `pnpm dev`，使用 development 模式；`.env.development` 默认连接本机后端。需要跨机器访问时按部署环境配置后端地址及代理，不使用测试库的账号配置作为生产配置。

工时差异升级同时创建站内信模板及默认停用的 `hrmPayrollWorkVarianceReminderJob`。生产启用前检查责任人/复核人主体授权和站内信配置；此轮只验证模拟发送、每日防重及失败重试，没有向真实人员发送提醒。工时差异台账与事件表包含来源证明，沿用工时查询权限及主体范围校验。

税务身份档案配置 `yudao.hrm.tax.identity-encryption-key` 与 `yudao.hrm.tax.identity-fingerprint-key`，或对应环境变量 `YUDAO_HRM_TAX_IDENTITY_ENCRYPTION_KEY`、`YUDAO_HRM_TAX_IDENTITY_FINGERPRINT_KEY`。二者均为独立生成的32字节随机密钥的Base64表示，由部署密钥管理提供，不写入Git；未配置时拒绝保存/核实敏感身份。加密密钥用于AES-GCM，指纹密钥用于跨记录身份匹配，不能随部署随机重置。旧数据迁移及密钥更换需受控重新加密/匹配迁移，不通过覆盖配置丢弃原数据。单元测试使用明确的测试专用密钥和虚构标识；普通JSON与审计快照不返回明文标识。

年终奖核算安装受控薪资项140101后，按租户执行既有薪资项目同步。该项税标记为false，税额依据批准年终奖模式单独生成或并入工资；不能复用通用奖金人工项代替。含旧税务来源且缺少批次奖金上下文的未发版本需重新核算。年度单独计税次数来自跨主体纳税人额度及已到账奖金证据，异常到账年/月仍需后续税务更正流程，原付款事实不改写。

个税申报页按已结束的实际到账月份生成准备文件，来源为成功付款与冻结税务结果。正式平台格式、申报及实际税款缴付由授权人员办理；本轮没有调用税务机关或银行接口。完整证件导出叠加税务私密信息权限及主体维护/复核授权，读取留痕，申报版本及普通查询仅保存脱敏信息和档案引用。缴退税凭证上传后须独立复核，退税关联原批准缴税记录并受累计额度限制，税款差额不自动改变员工工资或退款。政策、年度累计资料及期间异常的来源更正继续通过后续更正模块完善。

零实发准备只生成待结算记录，不自动生成到账日期或释放来源。结算人员核实实际会计抵扣/结清凭据后确认日期，不能由核算提交人本人确认，已确定日期及凭据不可改写。零实发不导出到银行，也不通过银行回盘确认；全部仍待零结算的批次可退回冻结后按正常解冻流程修订。历史零实发成功记录必须补齐与原日期一致的凭据才能进入税务累计，错误日期另走税务更正。

工资条投递升级：安装 `20261014-hrm-slip-delivery.sql`（可重复执行），配置 `hrm.salary-slip.portal-url` 为实际员工门户的 HTTPS 登录入口。站内通知模板随迁移创建；邮件、短信在 yudao 系统管理中分别配置 `hrm_salary_slip_delivery` 模板及渠道账号，参数为 `year/month/url`，正文只保留月份和登录入口。迁移创建默认停止的 `hrmSalarySlipDeliveryJob`；配置就绪后通过定时任务管理启用，不直接修改任务状态字段。该轮验证只使用模拟发送，没有发送真实邮件或短信。

工资条发布与投递队列同事务保存，工作任务先提交领取状态，再调用系统渠道。渠道日志成功代表通知已受理，阅读情况使用工资条已读记录。明确失败由授权人员重试，最多五次；未知结果保留核实状态，不能盲目重发。撤回删除有效工资条、取消待投递任务；已经送出的外部通知无法收回，但登录入口只能查询本人仍有效的工资条。通知链接使用登录入口，不携带薪资金额、身份号码或可直接读取工资的令牌。投递明细支持展开每次尝试的渠道日志、时间和错误类型。

税务来源更正升级：在已有零实发结算和税务档案升级之后安装 `20261014-hrm-tax-correction.sql`。入口为年度税务档案的实际到账年度台账，逐笔查看更正版本、提交正式依据并由另一名复核人批准。更正不修改银行到账事实或冻结工资；若存在同一納税人待发冻结批次，先按原流程完成发放或退回解冻再批准更正。该版本恢复年度台账读取，后续申报更正及税款清算仍在开发中。

员工税款结算升级：安装 `20261014-hrm-tax-settlement.sql`，入口为已完成正式完税对账的申报详情中的“员工税款结算”。依据批准申报核实差额及员工收付款确认，独立复核后，通过银行实际单笔流水/金额/日期/核实材料确认收退款。银行确认需要主体财务批准权限与支付回盘权限，不允许结算提交人或本人确认；批准申请不是实际付款。已批准未执行申请作废须留存银行未执行/作废依据，实际结清不可作废。

同一税务期间与收入类型的结算，跨申报版本按同一已核实纳税人汇总原有实际收退。年度工资预扣读取真实确认的收退款，明确区分工资税与单独计税奖金税，并按实际日期/年度归集；返还不增加工资收入或改变旧支付。已完成完税对账但员工税款差额未结清时，新的工资预扣阻断，申报查询和结算复核仍可继续。本版本使用独立银行收付款凭据流程，不自动发送银行指令。

工资差额升级：安装 `20261015-hrm-retro.sql` 后，按租户执行工资项同步，新增受控10901；授权核算审批页下的工资差额查询、登记和复核权限。常规目标批次须为草稿/已试算且有计划日期；原付款须已成功且有真实日期，零实发还需结算依据。核定金额指原工资计税收入（不含单独计税奖金和社保差额），正负差额由后续工资实际计算并按现金年度预扣。撤销仅限冻结前并须独立复核人员留据；变更后重算并重新审批。前次实际到账后才能接续下一次差额。此范围不发出真实银行指令；跨年收回不能直接扣当前年度税基。

独立工资补发升级：按顺序安装工资差额迁移与 `20261015-hrm-supplement.sql`。同时具有差额查询/登记及工资批次创建权限、主体读取/维护/核算授权的人员，可从成功银行明细创建独立补发。计划日期和当年度居民资料/扣除资料应先核实。到核算审批查询原工资期间对应的新补发批次，独立复核来源后试算，继续原审批冻结和银行回盘流程；批次保留原任职期间用于离职人员授权，税务累计使用实际到账年/月。独立补发不接收常规工资人工加项或年终奖，不重复计薪工作日和月度缴费，不能提交负银行代发。

成本分摊升级：安装 `20261015-hrm-cost.sql` 并授权成本查询、维护、复核及导出按钮。读取范围沿主体授权，规则登记另需主体维护/历史员工范围、规则复核需主体复核、报表编制需核算、报表批准需财务批准、导出需主体导出授权。确认配置金额是每个常规批次额外单位成本，独立补发不重复计入。报表只引用有完整历史归属及单位缴费来源的冻结工资，不为旧来源造零；先独立批准分摊规则，再编制并独立批准报表，最后导出。未来规则按有效日期覆盖前版，历史批准报告保留原金额；待审批报表遇到映射变化应重新编制。

预算与成本分析升级：先安装成本分摊迁移，再安装 `20261015-hrm-financial.sql`，授权分析查询、资料维护、独立财务复核、模板/分析导出。主体维护人员登记预算、营收和整数编制人数（金额元、人数人）；资料独立批准后进入指标。导入使用下载的当前模板，保留接续版本编号，预校验后整批提交，再独立复核。空白与零值含义不同，不能以空白制造零预算/营收/编制。成本批次须完成批准成本报告；分析按计薪年月和最新批准成本版本计算，导出携带来源编号，缺成本来源时阻断。不同范围类型分开展示/导出，人数不能跨范围叠加；银行到账月份仍另用实际到账台账。

工资结构与环比无需新增迁移，在已安装财务分析版本上进入同页面的“工资结构及环比”。来源为冻结工资的原工资项目录/结果及原计薪日归属，独立补发追溯原付款期间；计入应发的扣减显示为负。该口径与成本分摊部门不同，筛选的是原任职历史部门。缺本期或上期来源不以零替代，零/负分母比率不可计算。导出除分析导出权限外逐个校验涉及主体/工资批次的导出范围，并在期间业务履历留痕。
